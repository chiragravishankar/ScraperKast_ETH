# ScraperKast × KeeperHub — Autonomous Payment Agent

> **ETHGlobal Hackathon 2026 submission** — x402 payment rail integration on Ethereum Sepolia via KeeperHub execution layer.

An autonomous AI agent that discovers paywalled content, receives an HTTP 402 challenge, makes an autonomous pay/skip decision, routes the USDC micropayment through KeeperHub, and accesses the content — all without human intervention.

---

## What It Demonstrates

```
Bot discovers content
        ↓
  GET /api/test-content-eth
        ↓  (402 Payment Required)
  { amount: 1000 µUSDC, wallet: 0x..., network: "ethereum" }
        ↓
  Decision engine: is this worth paying for?
        ↓  (YES — HIGH relevance, AFFORDABLE)
  KeeperHub executePayment(agent, recipient, 1000n)
        ↓  (Ethereum Sepolia USDC transfer, confirmed ~15s)
  { txHash: "0x...", executionId: "exec_..." }
        ↓
  POST /api/test-content-eth/verify { txHash }
        ↓  (HMAC-SHA256 JWT issued)
  GET /api/test-content-eth  Authorization: Bearer <jwt>
        ↓  (200 OK)
  Content delivered 🎉
```

**Key integrations:**
- **x402 protocol** — HTTP 402 Payment Required as a machine-readable payment rail
- **KeeperHub** — execution layer handling Ethereum transaction submission, MEV protection, and gas abstraction
- **Autonomous decision engine** — keyword-overlap relevance scoring + affordability check before any payment
- **Ethereum Sepolia** — real on-chain USDC transfers (Circle testnet USDC)

## Quick Start

### 1. Prerequisites

- Node.js v18+
- Sepolia ETH (gas) — [sepoliafaucet.com](https://sepoliafaucet.com)
- Sepolia USDC — [faucet.circle.com](https://faucet.circle.com)
- KeeperHub API key — [app.keeperhub.ai](https://app.keeperhub.ai) *(optional — use `direct` mode without one)*
- Infura/Alchemy Sepolia RPC URL

### 2. Install

```bash
cd examples/autonomous-agent-keeperhub
npm install
```

### 3. Configure

```bash
npm run setup
```

This generates your agent wallet and writes `.env`. Then edit `.env`:

```env
PLATFORM_WALLET_ADDRESS=0xYourPlatformEthereumAddress
KEEPERHUB_API_KEY=kh_live_...          # from app.keeperhub.ai
ETHEREUM_RPC_URL=https://sepolia.infura.io/v3/YOUR_KEY
```

Fund the agent wallet printed by setup:
- **Sepolia ETH** (≥ 0.01) for gas → [sepoliafaucet.com](https://sepoliafaucet.com)
- **Sepolia USDC** (any amount ≥ 0.01) → [faucet.circle.com](https://faucet.circle.com)

### 4. Start the dashboard (in another terminal)

```bash
cd ../../apps/dashboard
npm run dev
```

### 5. Run the agent

```bash
npm start
```

Or run the full demo script:

```bash
npm run demo
```

## Testing Without KeeperHub

Set `KEEPERHUB_MODE=direct` in `.env` to bypass KeeperHub and send USDC directly:

```env
KEEPERHUB_MODE=direct
```

The agent still demonstrates the full x402 flow — KeeperHub is swapped for a direct `ethers.js` transfer. This is ideal for local testing without an API key.

## KeeperHub Integration Details

### Execution flow (KeeperHub mode)

```typescript
// 1. Agent signs payment authorisation
const signature = await signPayment(wallet, usdcAddress, recipient, amount);

// 2. Submit to KeeperHub API
POST /v1/executions
{
  type:      "erc20_transfer",
  network:   "sepolia",
  from:      "0x<agent>",
  to:        "0x<usdc_contract>",
  calldata:  "<abi.encoded transfer(recipient, amount)>",
  signature: "0x<agent_sig>",
  metadata:  { project: "ScraperKast", protocol: "x402" }
}

// 3. Poll for confirmation
GET /v1/executions/:id
→ { status: "confirmed", txHash: "0x...", blockNumber: 123456 }
```

### Why KeeperHub?

| Without KeeperHub | With KeeperHub |
|---|---|
| Agent manages gas estimation | Gas abstraction — KeeperHub handles it |
| Single RPC endpoint, single point of failure | Multi-RPC with automatic failover |
| Susceptible to MEV / frontrunning | MEV protection built-in |
| Manual retry on dropped transactions | Automatic retry with escalating gas |
| Agent holds ETH for gas + USDC for payment | Can pay gas from USDC balance (future) |

## Decision Engine

Before paying, the agent evaluates two axes:

**Relevance** — keyword overlap between `AGENT_GOAL` and the content description:
- `HIGH` (≥35% overlap) → proceed if affordable
- `MEDIUM` (≥15%) → proceed if affordable
- `LOW / NONE` → proceed only if price ≤ 5000 µUSDC

**Affordability** — compares USDC balance against price and max price:
- `AFFORDABLE` → balance ≥ amount AND amount ≤ MAX_PRICE
- `EXPENSIVE` → amount > MAX_PRICE (skip)
- `UNAFFORDABLE` → balance < amount (skip)
